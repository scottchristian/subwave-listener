# Issue Logging Rules

When you are asked to log a bug report or a feature request, you MUST follow these guidelines to ensure meaningful information is provided.

## 1. Title Format
All issue titles must begin with the appropriate tag:
- For bugs: `(bug) [Title]`
- For features: `(feat) [Title]`

## 2. Feature Requests (feat)
When logging a feature request, you must:
- Use as few words as possible.
- Be direct and to the point.
- Clearly state what you want the feature to do.
- Clearly state what you are expecting the outcome to be.

**Example of a good feature request description:**
> when using the like song feature, it should be able to sync all those likes back to my software platform of choice.

## 3. Bug Reports (bug)
When logging a bug report, you must provide meaningful information that helps identify and resolve the problem, including what the bug is, what is happening, and what should be happening.

# Templates

Use the following templates when creating issues.

### Feature Request Template
```markdown
# Title: (feat) [Short, direct title]

## Description
[Direct, concise explanation of what the feature is and what it should do, using as few words as possible.]

## Expected Outcome
[What you expect the outcome to be.]
```

### Bug Report Template
```markdown
# Title: (bug) [Short, descriptive title]

## Description
[Clear, meaningful explanation of the bug.]

## Steps to Reproduce
1. [Step 1]
2. [Step 2]

## Expected Outcome
[What should have happened.]

## Actual Outcome
[What actually happened.]
```
